1. O microcontrolador — o cérebro do dispositivo
O mais indicado para vocês é o ESP32. É brasileiro no ecossistema (amplamente fabricado e usado aqui), barato (em torno de R$20-40 a unidade), tem Wi-Fi e Bluetooth nativos, suporta módulos GPS externos, e tem comunidade enorme. Para o pitch, o argumento "hardware nacional acessível" se sustenta bem com ele.

2. O módulo GPS
O ESP32 não tem GPS nativo — você acopla um módulo externo. O mais usado é o NEO-6M ou NEO-8M da u-blox. Ele recebe sinal de satélite (GPS/GLONASS) e entrega coordenadas via serial para o ESP32. Custo: R$30-60.
Fluxo: satélite → módulo GPS → ESP32 recebe latitude/longitude

3. Como reter as informações do veículo (placa, tipo, etc.)
Essas informações não precisam ficar no hardware — ficam no servidor/software, vinculadas ao ID único do dispositivo. O dispositivo só precisa saber quem ele é (um ID fixo gravado na memória do ESP32) e onde está (GPS). O software cruza: "dispositivo ID-047 = caminhão pesado, placa XYZ-1234".

4. Comunicação — como os dados chegam ao software
Aqui está a decisão mais importante. Três opções realistas:
4G/LTE — módulo SIM800 ou SIM7600 acoplado ao ESP32. O dispositivo envia os dados via internet móvel direto para um servidor. Simples, funciona em qualquer lugar com cobertura. Custo do módulo: R$80-150. É a opção mais fácil de demonstrar.
LoRaWAN — módulo Ra-02 ou similar. Longo alcance (até 15km em área aberta), baixíssimo consumo, mas precisa de um gateway LoRa instalado no porto. Ideal para escala, mas adiciona infraestrutura. Para o pitch, é o argumento técnico mais robusto.
Wi-Fi — já nativo no ESP32. Funciona se o porto tiver cobertura Wi-Fi industrial. Mais simples, mas menos convincente para área externa grande.
Recomendação para o pitch: propor LoRaWAN como tecnologia principal (robusto, escalável, baixo custo por dispositivo) e 4G como fallback. Isso mostra maturidade técnica.

5. Como o software recebe a localização
O fluxo completo seria:
ESP32 + GPS → coleta coordenadas a cada X segundos

MQTT é o protocolo mais usado nesse tipo de IoT — leve, feito para dispositivos com recursos limitados, e tem brokers gratuitos para protótipo (como o HiveMQ ou Mosquitto).

O que isso significa em decisões concretas:
Fundo branco ou off-white quase puro. Superfícies diferenciadas por tons muito sutis de cinza — não por sombras dramáticas. Bordas finas, 0.5px a 1px, cinza claro. Sem gradientes. Sem dark mode agressivo. Sem brilho, glow, neon.
Tipografia com peso leve a regular — nunca bold pesado. Hierarquia feita por tamanho e opacidade, não por cor chamativa.
Acentos de cor mínimos — só para status crítico (vermelho para interdição, verde para online, amarelo para alerta). O resto é preto, branco e cinza.
Ícones simples, lineares, finos. Sem preenchimento.
